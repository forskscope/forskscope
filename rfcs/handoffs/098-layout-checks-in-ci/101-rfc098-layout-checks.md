## Stage A: the prototype and its cost, then stop for my answer

1. **The `layout-probe` Cargo feature** in `crates/forskscope-ui`, off by
   default:
   - a plan file read through an environment variable that exists only in
     this build;
   - in-process state changes through the settings signals;
   - views opened from fixtures;
   - a settle condition, **not a sleep**;
   - a measurement script run through `document::eval`, the script itself
     compiled in only with the feature;
   - one JSON result per view and combination, then exit.
2. **Fixtures generated by the driver, not stored.** CI can't see
   `.git-exclude/`. `cargo xtask layout-check` writes the fixture tree
   deterministically into `target/layout-check/`, from code, as
   `xlsx-fixtures` does: a folder pair with every status that a fixture can
   produce, a file pair with a collapsed region and a replace, and a
   mergetool triple. **Nothing from the maintainer's machine.**
3. **One check end to end: overflow and clipped text.** Run it on two
   views, the file comparison and Settings, across the full size,
   language and window axes.
4. **Measure the cost:**
   - the time per measurement;
   - the time per app run;
   - the projected full-matrix time on CI.

   Run one **CI job** that installs `xvfb`, `dbus-x11`, `fonts-noto-core`
   and `fonts-noto-cjk`. It is a push-triggered job on a scratch branch,
   authorized, deleted afterwards.
   - Locally, run it under the nested niri through `session.sh` instead.
     `xvfb-run` isn't installed here, and the probe doesn't depend on the
     display.
5. **Retroactive proof, for this one check:** run it on the commit before
   F217's fix (`545298f`, the stacked labels) and before F218's
   (`545298f`, the collapsed content). **It must report both.**

## Stage B: the full set (after my answer to 188)

- **The remaining checks** (RFC §2): off-screen controls, hit area,
  rendered contrast, text size. Each allowance is a named entry with its
  reason, printed on every run, as the `contrast` gate prints its
  allowlists.
- **The remaining views:** the Explorer, Deep Compare with a selected row,
  the mergetool, *Shortcuts*.
- **`--inject <defect>`** for each check: an overflowing label, an
  undersized button, a low-contrast pair, 11 px text. Each must fail.
- **A capture of each failing view,** in its combination, as a CI artifact.
  It's taken only on failure.
- **The release check:** `release.yml` fails if the probe's marker string is
  in the release binary, beside the existing `show_to_person` seam check.
  Falsify it with a build that has the feature on.
- **CI wiring:** the job on every push and pull request, plus the nightly
  and release-commit schedule if my answer to 188 splits the matrix.
- **Retroactive proof, full:** F217, F218, F219 and F220. Check out the
  commit before each fix and show the job reports it.
- **Docs:**
  - `docs/src/maintainers/testing.md`: the gate and how to run it locally;
  - **a paragraph for the GUI rules,** which **you show me first,** because
    the rules file is the owner's.

## Rules

- **The GUI rules apply to the real-UI parts:**
  - isolation;
  - one instance;
  - fixtures only;
  - the evidence plan stated first.
- **The probe never reads or writes outside its plan's fixtures and its
  results file.** No network.
- **Test names are diffed** before and after.
