# Handoff 039 — RFC-080 tier 1: directory rows answer "do these differ?"

**From:** architect. **Date:** 2026-09-24. **Release:** 0.172.0.

## The one asymmetry everything follows from

> A cheap scan can prove two directories **differ**. No cheap scan can prove
> they are **identical**.

A tier-1 pass that finds nothing must never render as equal, and must never be
hidden by the *hide identical* filter.

## 1. The verdict, as a pure function (`forskscope-ui-logic`)

Core already gives you everything and **no verdict**:
`list_recursive_for_display_with_cancel(left, right, token) -> RecursiveScan`
(`crates/forskscope-core/src/dir/recursive.rs:143`) records `left_size` /
`right_size` per entry and marks common files `Computing` **regardless of
whether the sizes differ** (`:364-374`). Tier 1 is caller-side folding over
`RecursiveScan`. Do not add the size comparison inside core: `RecStatus` is
shared with Deep Compare and its meaning must not shift underneath it.

Add a module beside `explore/deep_filter.rs`, taking `&RecursiveScan` (it needs
the root flags, not only the entries) and returning a three-state verdict:

- **Different** — any entry present on one side only, **or** any common file
  whose `left_size != right_size`. Certain.
- **Unknown** — any `RecStatus::Unreadable`, any `RecStatus::Symlink`, or
  either `left_root_unreadable` / `right_root_unreadable`. Never a verdict
  (criterion 4, and §2's symlink paragraph).
- **MetadataMatch** — otherwise. Names and sizes match; contents were never
  read.

**Order matters:** *Unknown* outranks *Different* only where the unreadable
entry could itself be the difference — an unreadable entry means the walk did
not see everything, so a `MetadataMatch` derived from the rest is not
trustworthy. A one-sided entry, however, is a fact the walk did establish.
**Decide the precedence explicitly, write it in the module doc, and test both
orders of input.** My ruling: a definite *Different* from a one-sided entry or
a size mismatch stands even when another entry is unreadable; *Unknown* wins
only over *MetadataMatch*.

Keep it a free function over borrowed data, unit-testable with no Dioxus
runtime, as `deep_filter.rs` is.

## 2. The status state (core + ui-logic)

RFC-080 §4 settles five states. Four exist. **Tier-1 match does not, and the
two nearby variants must not be reused:**

- `EqualityEvidence::MetadataEqual` counts as **equal** (`is_equal`,
  `crates/forskscope-core/src/dir/index.rs:212`). Using it would assert what
  tier 1 cannot.
- `EqualityEvidence::MetadataOnly` is **taken**: the Explorer inserts it as the
  "digest in flight" placeholder (`explorer.rs:377-380`) and
  `RowStatusKind::from_evidence` maps it to `Computing`
  (`crates/forskscope-ui-logic/src/explore/status.rs:197`). Reusing it would
  give every tier-1 match a spinner that never resolves.

So: **add a new variant** to `EqualityEvidence`, to `RowStatusKind`, and to
`StatusGlyph`. Name it for the evidence, not for a guess — `MetadataMatch`
unless you have a better one; nothing named `Maybe*` or `*Equal`.

- `is_equal`, `is_different` and `is_pending` must all be **false** for it. It
  is a completed measurement with an incomplete conclusion.
- The *hide identical* filter keys off `is_equal`
  (`crates/forskscope-ui/src/ui/view/explorer/filter.rs:147-165`), so a
  tier-1 match must stay visible. Confirm that, don't assume it.
- **Glyph: `≈`** — my call, and the owner may overrule it. The status column
  renders only a glyph (§4); the label carries the precision. Add its
  `css_class()` token, and note that `crates/forskscope-ui-logic/tests/css_coverage.rs`
  requires the class to exist in the stylesheet.

**Every match site on the enums you extend needs an explicit decision, not a
catch-all arm.** At minimum: `RowStatusKind::needs_action` (`status.rs:175`),
`StatusGlyph::for_rec_status` (`:108`), and the Explorer's filter. Where a site
is data-destructive — anything gating a copy or a merge plan — a
`MetadataMatch` must never be treated as *equal, skip* nor as *different,
copy*. List the sites you touched in the reply.

## 3. The labels (§4)

Same state, different words by row kind:

| Row kind | Label |
|---|---|
| File | Size matches; contents not compared |
| Directory | Names and sizes match; contents not compared |

`status_kind_label(kind, lang)` (`crates/forskscope-ui/src/ui/view/dir_pane.rs:38`)
does not take `is_dir`; `TreeRow` already knows it (`:260`). Change the
signature rather than guessing at the call site. Japanese entries for both, so
`cargo xtask i18n` covers them.

## 4. The trigger: on selection, debounced (§5, criterion 7)

Today selection only sets `on_selected` / `left_pick` / `right_pick`
(`explorer/tree.rs:186-190`, `:226-230`). There is no timer anywhere in the
crate.

- **Interval: 250 ms.** My decision, so it is recorded rather than
  rediscovered: key repeat during arrow-key navigation is far faster than
  that, so a row must genuinely be rested on before anything starts, while
  250 ms still reads as immediate. Put the number in one named constant with
  that reasoning in its doc comment.
- **Arrowing through rows must start no walk** (criterion 7). Prove it, see
  §7.
- **At most one tier-1 walk in flight.** Selection moving, or the pane
  navigating, cancels it. That also spares you a second concurrency bound:
  the existing `DigestEpoch`
  (`crates/forskscope-ui/src/ui/view/digest_epoch.rs:31`) already owns
  generation, token and semaphore, and §5 is written against it. **Do not
  introduce a second cancellation mechanism.**
- **Make the debounce a pure state machine** in `ui-logic`: selection events
  and a caller-supplied instant in, "start a walk for this row" out. Then it
  is unit-testable without a runtime and without sleeping in tests. The view
  supplies the clock and the spawn.

## 5. Caching and invalidation (§5)

- Key on **(left_root, right_root, rel_path)**.
- **Not in `digest_map`.** Every tree expand clears that map wholesale
  (`explorer/tree.rs:182`, `:242`; `explorer/compact.rs:76`, `:131`), so a
  tier-1 verdict stored there would be destroyed by an unrelated toggle. Use a
  separate signal with its own invalidation, cleared on navigation and refresh.
- No persistence across sessions, and no filesystem watching (§Non-goals).

## 6. Accessibility (criterion 6)

- Every new state needs a localised `aria_label`, matching the Explorer's
  existing `role="img"` + `aria_label` pattern (`dir_pane.rs:337-350`). Add no
  third pattern (§6).
- **Completion must be announced**, not silently swapped in. Find whether the
  app already has a polite live region; reuse it if so. If none exists, add
  one minimal region in the Explorer and say in the reply that you added it.

## 7. Verification

Each check must be **shown failing** against a deliberately broken input, and
**not** against a helper this change introduces (review 072's lesson).
Real temporary trees, following `temp_dir(tag)` in `explorer.rs:592-770`.

1. **Criterion 1** — pair differing only in a file's size: *Different*, and
   **no contents read**. Prove the "no reads" half, do not assert it: a file
   whose contents differ at identical size in the same tree must not change
   the verdict.
2. **Criterion 2, tier-1 half** — differing contents at identical size:
   *MetadataMatch*, never *Different*.
3. **Criterion 3, tier-1 half** — identical pair: *MetadataMatch*, **never
   `Identical`** from tier 1 alone.
4. **Criterion 4** — unreadable entry, unreadable subdirectory, and unreadable
   **root** (use `RecursiveScan`'s flags; a `chmod 000` directory under a
   `#[cfg(unix)]` test is the obvious way): *Unknown* in all three, and in
   particular neither a verdict nor a tier-1 match.
5. **Criterion 5** — navigating away cancels an in-flight walk, and no result
   lands in the view. **Observe the token, do not assume it** (the F61
   pattern).
6. **Criterion 6** — non-empty localised label for every new state, in both
   languages; the Japanese one must differ from the English one, as
   `webview2.rs`'s test now does.
7. **Criterion 7** — moving through rows starts no walk. Drive the debounce
   state machine with a sequence of selection events and a fake clock, and
   assert the walk count is zero until one row is rested on past the interval.
8. **A symlink** on either side yields *Unknown*, not a verdict (§2).

Also run the gates that this change can break by construction: a new `ui-logic`
module needs rows in **both** doc tables (`cargo xtask ui-logic-docs`), and any
new crate-root export needs a real consumer in `forskscope-ui`
(`cargo xtask ui-logic-connectivity`).
