# Handoff 060 — RFC-080 tier 2: the certain answer

**From:** architect. **Date:** 2026-10-01. **Release:** `0.175.0`.
**RFC:** `rfcs/accepted/080-explorer-tiered-directory-comparison.md` §3, §4, §5.
**Register:** also closes **F145**. **Take handoff 059 first** — F135's answer
may change what the walk reports, and this is built on that output.

## 1. What tier 2 is

Tier 1 answers *do these differ?* from names and sizes, reading no contents.
Tier 2 answers *are these identical?* definitively, by running
`recursive_diff_with_cancel` and reading them.

**The trigger is the owner's decision (§3, Q1 closed 2026-08-22): user-initiated,
per row.** Not automatic under a size budget — nobody has calibrated such a
budget, and a budget becomes a claim of its own.

Two consequences the RFC tells you to build to rather than rediscover:

- **The control appears only on a row already at the tier-1 match state.** A row
  proven *Different* needs no verification; a row at *Not compared* has no
  tier-1 result to escalate from. Offering it everywhere invites the expensive
  pass exactly where it is least useful.
- **Several rows may run at once**, so they share the same bound and
  cancellation as everything else (§5). Six *verify* clicks are six answers, not
  six unbounded fan-outs. Tier 1 already has one `DigestEpoch` instance at
  concurrency 1 — reuse that mechanism, do not add a second.

## 2. Acceptance criteria 2 and 3, tier-2 halves

These are the halves tier 1 left open, and they are what this handoff is judged
against:

- **Criterion 2:** a pair differing only in file *contents at identical size*
  reads at the tier-1 match state after tier 1, and **`Different` after tier 2**.
- **Criterion 3:** an identical pair reads at the tier-1 match state after tier 1
  and **`Identical` after tier 2** — and **never `Identical` from tier 1 alone**.

Criterion 3's second clause is the one to keep a test on permanently. Tier 1's
whole discipline is that it never claims identity; tier 2 is the only thing
entitled to, and the easiest way to break that is to let a tier-2 result repaint
a row that tier 2 never examined.

Criteria 4, 5 and 6 are already satisfied by tier 1 and must stay satisfied:
unreadable anything is `Unknown` and not a verdict; navigating away cancels and
no result lands in a view the user has left; every state has a non-empty
localised accessible label and completion is announced.

## 3. Status vocabulary — settled, do not re-open

§4's table is decided. The status column renders **only a glyph**; the wording is
the `title` and `aria_label`, so there is no column width to economise against.
`Identical` is labelled *Identical — contents compared* on both file and
directory rows, and is reachable **from tier 2 only**.

If a state you need is not in that table, that is a question for me, not a value
to invent.

## 4. F145, while you are in this code

## 5. Verification

1. **Criterion 2 end to end**, on a real pair: same size, different content —
   `≈` after tier 1, `Different` after clicking verify.
2. **Criterion 3 end to end**, and the clause that matters: a test that fails if
   `Identical` can ever be reached without tier 2 having run.
3. **The control's placement**, proven by absence as well as presence: it is
   offered on a tier-1-match row and **not** on a `Different` row, a *Not
   compared* row, or an `Unknown` row.
4. **Concurrency and cancellation**: several verifies at once stay bounded;
   navigating away cancels in flight and no result lands afterwards. Observe the
   token rather than assuming it, as tier 1's criterion 5 did.
5. **Accessibility**: the new state's label is non-empty in both languages and
   completion is announced — tier 1 added the live region, so announce into it.
6. **In the real app**, not only in tests.
